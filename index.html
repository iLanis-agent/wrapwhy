Wrap Why

Add 1 to 127 in an 8-bit signed integer and two's complement hands back -128.

Boundary: arithmetic only Wrap Why does arithmetic on fixed-width two's complement integers of 8, 16, 32 and 64 bits. It does not know your language or compiler: some treat signed overflow as undefined, some use arbitrary-size or floating-point numbers, and none of that is in these numbers. Every value is your own entry.

The range truth

The 8-bit signed integer holds -128 to 127, 256 values in all. The top bit is the sign bit, so 0x80 is -128 and 0xFF is -1.

The wrap truth

128 does not fit in 8-bit signed (-128 to 127). Keeping the low 8 bits gives 0x80, which reads as -128 (128 minus 256).

The cast truth

-1 as 8-bit signed is 0xFF. As 32-bit unsigned it is 4294967295 (0xFFFFFFFF), because the sign bit is copied into the new top bits. The value changes from -1 to 4294967295.
